# 忆伴 MemoryMate 开发交接说明

## 交接结论

APK是编译后的安装产物，用于体验与安装，不包含可直接维护的原始Vue单文件、TypeScript类型、开发脚本与原始项目组织。接手开发应使用本包的 `mobile/` 源码，再把APK作为行为参照。

支持项目文件、依赖安装和终端的AI开发工具可以继续修改、运行和构建本工程。仅支持聊天或不能解压/运行代码的工具，需要先由用户解压并提供相应文件。账户发布权限不会随源码压缩包自动转移。

## 当前范围与架构

- 产品：面向长辈与家属的认知活动、家庭记忆与陪伴Demo；两个模式，各5项主导航，共38个实体页面。
- 栈：uni-app、Vue 3 Composition API、TypeScript。Vue 3.4.21，Vite 5.2.8，DCloud包全部锁定为 `3.0.0-5020620260917001`，匹配HBuilderX 5.26。
- 当前没有真实账号、云端用户数据库、跨设备同步、AI模型服务、真实语音识别或系统推送。下一位AI应继续保持这个范围，除非用户提出新需求。
- 数据路径：页面 → `stores/family.ts` → `api/repositories.ts` → 集中Mock与 `uni` 本地存储。家庭资料命名空间为 `memorymate.v1.database.v2`。
- 两种模式共享同一设备中的数据。演示注册、邀请、绑定、授权开关不能当成真实认证和服务端权限。
- `mock/data.ts`、`database.ts`、`catalog.ts`、`companion.ts` 集中维护虚构资料、题库、示例音频和模拟回复；素材已打包在 `src/static/`。

## 修改入口

| 工作 | 主要文件 |
| --- | --- |
| 启动、注册、身份与首页 | `src/pages/welcome/`、`auth/`、`elder/home.vue`、`family/home.vue`；注册逻辑在`modules/account/AccountScreen.vue` |
| 人物、故事、相册与编辑 | `modules/memory/MemoryScreen.vue`、`MemoryEditor.vue` |
| 五类训练、答题、结果与历史 | `modules/training/TrainingScreen.vue`、`mock/catalog.ts` |
| 模拟AI陪伴 | `modules/companion/CompanionScreen.vue`、`api/ai.ts` |
| 健康任务与观察 | `modules/health/HealthScreen.vue` |
| 留言、重要日期 | `modules/family/InteractionScreen.vue` |
| 公共视觉 | `styles/`、`components/`、`layouts/AppLayout.vue` |
| 路由 | `config/routes.json`，再运行`npm run pages:generate`同步`pages.json` |
| 数据事务与校验 | `stores/family.ts`、`api/repositories.ts`、`utils/storage.ts` |
| 不同故事对应照片、旧示例图兼容 | `utils/presentation.ts`、`api/repositories.ts` |

`pages/`中的多数文件是薄入口，业务在`modules/`，不应把薄入口误判为未实现页面。`generate-assets.mjs`是早期素材生成器，会覆盖当前部分SVG颜色和旧插画，日常开发不要盲目重跑。`connect-modules.mjs`是初次建立入口的辅助脚本，正常改功能不需要再次执行。

## 在新环境运行

解压后进入项目根目录，再执行：

```powershell
cd mobile
npm ci
npm run check
npm run dev:h5
```

需要Node 22或更新版本及npm。本次环境的精确版本和验证状态见`handoff/environment.json`、`handoff/VALIDATION.md`。不要从旧机器复制node_modules。

构建网页执行`npm run build:h5`，输出`mobile/dist/build/h5`。构建App资源执行`npm run build:app`，输出`mobile/dist/build/app`；后者仍不是APK。跨机器H5开发不需要HBuilderX账号；Android标准基座运行和云打包需要安装相应工具。

## 更新已发布网页

主要地址：`https://dh202667-netizen.github.io/memorymate/`。

公开仓库 `dh202667-netizen/dh202667-netizen.github.io` **只存放H5构建产物，不是源码仓库**。当前已发布提交、分支及备用平台信息在`publish/deployment.json`。网站的根目录和`/memorymate/`是两个入口，资源在根目录，因此不要把构建目录直接改成只发布子目录。

本地准备新发布文件：

```powershell
cd mobile
npm run check
npm run build:h5
npm run prepare:github
```

`prepare:github`只生成`publish/github-pages/`副本，不推送或上线，保留目录中的`.git`和其他根文件。存在Git仓库时会检查origin，避免修改其他仓库。完整包中的该目录为冻结网页快照，没有Git凭据；源码包会按上述命令重新生成。

需要更新原站点时，由用户授权有写权限的GitHub账号。在独立空目录克隆原仓库，确认origin和main分支，再同步已验证的生成文件、审查diff、提交推送。无需新增用户数据库。若换成另一个账号，可使用自己控制的新仓库发布，但原网址不会随源码自动转移。

旧Sites地址用户反馈微信内拦截，不作为主地址。其公开标识保留在部署元数据中，不默认恢复或自动创建新Sites。

## 继续生成Android APK

当前标识与冻结安装包：

- DCloud AppID：`__UNI__5CEFF0E`；包名：`com.memorymate.demo`。
- 版本：0.3.0，versionCode 300；Android云端证书归原DCloud账号管理。
- APK仅含arm64-v8a，minSdk 21，targetSdk 28。现阶段是内部Demo，不是已经完成应用商店适配的版本。
- 原始APK、大小、SHA-256及签名核验见`releases/`。源码包只带核验文件，完整包另带APK。

使用HBuilderX 5.26，登录用户授权的DCloud账号；正式打包已使用普通云打包。安心打包曾在本地生成阶段失败，不应在没有修复证据时反复重试。源代码已配置Camera模块，支持现有相册选择功能，没有加入实际录音模块。

检查配置（不会提交云打包）：

```powershell
cd mobile
.\scripts\package-android.ps1 -Action Check -HBuilderPath '你的HBuilderX安装目录'
```

用户要求打包后，再执行同一脚本的`-Action Build`。它使用云端证书和固定包名；DCloud登录、手机号验证、额度或付费提示仍由平台与用户控制。CLI有时错误时仍退出0，必须看最终打包状态、下载文件并校验，不能凭退出码宣称成功。

更新现有安装应用需保留包名与原签名，版本号也需递增。不要把换账号后生成的新签名当成原应用的可覆盖更新。DCloud AppID和签名的访问权不在源码包中；如要转移发布所有权，应由原用户在官方平台处理授权/证书管理。不要把私钥或账号密码上传给AI聊天。

## 实际验证与已知限制

历史UI验收有114项屏幕/字号组合检查、33组模块场景和4组UI交互；线上注册另有4项验证。详情在06、07、09号文档，不能把历史结果说成本次重新执行的结果。

0.3.0独立APK已通过包名、版本、v1/v2签名与内置资源核验，但尚未完成这份APK的真机安装验收。此前REDMI上的官方基座测试不等于独立APK测试。真机系统返回、相册授权、媒体选择与不同Android版本仍需针对实际安装包验证。

QA脚本位于`scripts/qa/`，使用Playwright CLI的原始函数表达式，不是Jest或Node直接入口。可用`npx --yes --package @playwright/cli@0.1.24 playwright-cli`调用；本机原使用的绝对缓存路径不是项目依赖。先创建根目录`output/ui-refresh`，启动独立测试浏览器，再按QA README运行。memory/integrity会删改该测试会话的本地资料，绝不能用于用户正在体验的页面。

改路由标题需同步QA中相应预期。网页大图与托管网络可能影响首次加载，后续可在保持故事内容一致的前提下评估体积与加载优化；不要未经实测声称已经改善。

下一步优先：独立APK真机验收，其次按用户需求完善Demo。真实数据库、AI服务和跨设备家庭同步不在当前用户授权范围内。

## 交接中没有包含什么

没有包含node_modules、IDE/SDK安装程序、浏览器或手机本地家庭数据、账号密码、访问令牌、签名私钥、用户真实上传媒体。源码包包含虚构示例照片及本地示例音频，图片提示词见08号文档。

本次打包校验与新环境构建只针对交接副本；没有自动重发网站、生成新的云端APK或改变现有用户资料。包内源码可继续开发，但不能保证与已发行APK逐字节重建一致，因为云端原生工具链与签名过程也属于构建环境。
