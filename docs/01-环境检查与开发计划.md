## 产品范围与决策

- 一个应用、一个演示家庭、老人/家属两个模式。原型切换模式是体验入口，未来不是权限授予方式。
- 首屏优先呈现陪伴和日常活动；不生成疾病诊断、治疗承诺或医疗风险分。
- 当前不收集真实手机号、密码、录音或照片；演示入口使用固定虚构家庭。
- 用统一自定义底部导航表达双模式，一级入口 `reLaunch` 避免页面栈累积，详情 `navigateTo`，返回有首页兜底。
- `pages.json` 从类型化路由清单生成；所有页面实体存在。未完成业务的页面统一标为「页面骨架」，不可把占位页当成功能完成。
- 页面只依赖 repository 和 service，不直接导入 mock；后续替换适配器接 FastAPI。
- 首版使用 Vue 响应式单例 store，保留本地偏好；规模增长后可迁移 Pinia，当前避免额外复杂度。

## 后续每轮的完成定义

1. 老人端：人物→详情→照片大图；故事→详情→关联人物；五类活动→答题→结果→历史；AI模拟文字及录音状态；任务记录；偏好设置。
2. 家属端：人物新增/编辑和校验；本地照片/语音附件元数据；故事、时间轴、关系管理；活动图表和家属观察新增；留言、日期提醒。
3. Mock：统一延迟与错误、空列表、跨模式刷新、本地演示数据清理；不承诺媒体已上传云端。
4. 最终：完整走查登录→身份→两端全部入口；Android 360/390/412 宽度、大字模式、系统返回、安全区、权限拒绝和无网络状态。
